## Security & API Key Storage

> [!IMPORTANT]
> API keys entered via the initial setup screen are stored in **plain text** within a JSON file in your OS's default configuration directory (e.g. `~/.config/zizou/config.json`). They are **not encrypted**.

To avoid writing your key to disk entirely, provide it via environment variables instead — env vars always take precedence over stored keys.

## Guardrails & Execution Control

Zizou enforces human-in-the-loop security boundaries:
- **Zero Autonomous Writes:** File writes or modifications are shown as a diff and require approval before execution.
- **Zero Autonomous Command Runs:** Shell commands must be explicitly approved by the user before running.

## Architecture Deep Dive

The core of Zizou is built around real-time streaming and automatic tool execution. Here's a breakdown of how the UI communicates with the LLM through `runTurn` and `streamText`.

### HIGH-LEVEL FLOW

```
    UI (React/Ink)
      │
      │ user hits Enter
      ▼
    runTurn (agent loop) ──▶ resolveModel (config + api key)
      │
      ▼
    streamText (AI SDK) ──▶ LLM API
      │
      ├─▶ [Stream Text Chunks] ──▶ Updates terminal text-by-text
      │
      └─▶ [Stream Tool Calls]
            │
            ▼
        executor (agent) ──▶ Intercepts & Captures Pre-Execution File State
            │
            ▼
        execute() ──▶ Prompts User for Confirmation (if write/run)
            │
            ▼
        Returns Tool Result message to LLM
```

### Model Configuration (`resolveModel`)

Before any chatting begins, the system must set up the connection to the requested AI provider. This happens in `src/provider/resolve-model.ts`. It fetches the API key from local storage or environment variables, instantiates the Vercel AI SDK provider factory (like `createGroq`), and returns a ready-to-use `LanguageModel`.

### Why Streaming?

When an LLM writes code, the response can be thousands of tokens long. If we waited for the entire HTTP request to finish, the user would stare at a frozen terminal for 20-30 seconds.

**Streaming** solves this. The API sends the response back chunk-by-chunk. The `streamText` function reads this stream in real time and updates the screen token-by-token.

### The Interception Loop (`runTurn` & `executeStep`)

While `streamText` is handling the network and executing tools, the terminal UI needs to know what is happening so it can draw text or display loading badges.

This is the job of `runTurn`. It acts as a wrapper around `streamText`, iterating over the `result.fullStream` in real-time, translating the raw AI SDK stream parts into clean `AgentEvent` objects for the React UI.
Additionally, when a tool-call for a file modification (such as `writeFile` or `editFile`) is received, the executor intercepts it **before** execution to capture the file's current content as `oldFileStates`. This is crucial for Zizou's independent version-control and diffing engine.
